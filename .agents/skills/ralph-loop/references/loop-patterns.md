# 루프 엔지니어링 패턴 (Loop Engineering Patterns)

본 문서는 `수형 (SOOHYUNG) / 가지톡 (GajiTalk)` 프로젝트에서 즉시 활용할 수 있는 대표적인 4대 루프 엔지니어링 패턴을 정의한다.

---

## 1. TDD 수렴 루프 (Red-Green-Refactor Loop)

### 목적
- 실패하는 테스트를 작성하고, 코드를 작성해 통과시킨 후, 리팩터링하는 과정을 완료 조건 충족 시까지 자동 반복.

### 워크플로우
```text
[테스트 실행] ──실패──▶ [원인 분석 및 최소 코드 수정] ──▶ [재테스트]
      │                                                        ▲
      └────────────────통과────────────────────────────────────┘
```
- **완료 약속 (Promise)**: `ALL_TESTS_PASSING` (모든 단위/E2E 테스트 통과 및 회귀 없음)
- **최대 반복수**: 5~10회

## 2. 결함/에러 제로 루프 (Zero-Defect Lint/Type/Build Loop)

### 목적
- `./apps/mobile-app`(:30018), `./apps/admin-web`(:30019), `./apps/backend`(:30020) 전체 빌드 시 린트 에러, 타입스크립트 컴파일 에러, 브라우저 콘솔 경고를 0건으로 수렴.

### 워크플로우
- 매 반복마다 `./compile.sh all`을 실행하여 남은 에러 개수 $E_t$를 측정.
- $E_t = 0$ 이면 종료.
- 만약 $E_t \ge E_{t-1}$ 이면 회귀 경고 발생 및 이전 커밋 롤백 후 다른 수정 시도.
- **완료 약속 (Promise)**: `ERRORS_ZERO`

---

## 3. PRD 태스크 소진 루프 (Task Burn-down Loop)

### 목적
- `.agents/loop/task.md` 및 `docs/PRDs/WORK_ORDER.md`에 명시된 기능 요구사항 체크리스트를 하나씩 완료하며 체크박스(`[ ]` → `[x]`)를 갱신.

### 상태 파일 (`.agents/loop/task.md`) 예시:
```markdown
# 기능 구현 체크리스트
- [x] MongoDB 5대 컬렉션 스키마 및 시드 데이터 구성 (:30020)
- [x] 실사 절단선 오버레이(BranchOverlayCanvas) 및 생장 슬라이더 구현 (:30018)
- [ ] AI 시뮬레이션 첨부 조경사 견적 요청 및 입찰 비교 플로우 연동
- [ ] 관리자 Canvas 첨삭 스튜디오 및 조경사 명인 배지 심사 연동 (:30019)
```
- 매 반복마다 에이전트는 미완료(`[ ]`) 항목 중 최상위 1개만 선택하여 구현 및 테스트 후 `[x]`로 마크.
- 모든 체크박스가 `[x]`가 되면 `PRD_COMPLETED` 약속을 출력하고 종료.

## 4. 적대적 정제 루프 (Adversarial Refinement Loop)

### 목적
- 생성자(Builder)와 비판자(Critic)가 번갈아 실행되며, 비판자의 지적 사항(실사 몰입감 미흡, 시뮬레이션-매칭 데이터 단절, 수목 전지 용어 오류 등)이 모두 해결될 때까지 개선.
- Critic이 `CRITIC_VERDICT: APPROVED`를 내릴 때까지 반복 (최대 3회).
